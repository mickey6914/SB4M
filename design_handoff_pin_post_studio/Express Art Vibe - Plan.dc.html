1. What this app is (and is not)

Pinsflow's value was never the scheduling — it was turning one listing into thirty distinct, SEO-written pins in a couple of minutes. Content360 already does scheduling well, across more networks than Pinsflow ever will, and it exposes an API key on your workspace settings page.

So Pin-Post Studio is the generation and review layer. It owns: product ingestion, hero-image choice, scene direction, AI mockups, titles, descriptions, keywords, text overlays, and the fan-out decision (which pin also becomes a Facebook post and an Instagram post). It hands the finished assets and their post times to Content360 and never tries to be an inbox, a link-in-bio, or a sales bot.

2. The differentiator: one cross-network calendar

Neither tool shows you a single month where a pin, its Facebook echo and its Instagram post sit on the same row. That is the screen the whole prototype is built to earn. Concretely, when a run finishes you choose a fan-out pattern per pin — Pinterest only, Pinterest + Facebook, or all three — and Pin-Post Studio spaces them so the same product never lands twice in one day on one network. The calendar colour-codes by network, flags gaps ("Instagram is empty after the 14th"), and marks anything that failed to publish on the Content360 side.

Fan-out is a real design job, not a copy-paste: a pin is 2:3 and the other networks are not. Every fanned-out asset is re-cropped from the same mockup — 1:1 for a square feed post, 4:5 for the taller Instagram frame, 9:16 for a story or reel — with the text overlay re-positioned so it survives the crop rather than being sliced. The review grid shows all four ratios of a pin side by side, and rejecting one crop does not reject the pin.

4. Scale the design assumes

This was the question you wanted clarified — it only matters because it decides whether the calendar is a comfortable grid or a dense list. The assumption I've designed to: one brand, 30 pins a month, fanned out to three networks — roughly 90 scheduled posts, about three a day. That fits a normal month grid with 2–3 chips per cell and no scrolling inside a day. If you later run several shops, a brand switcher in the top bar covers it without changing the layout; if you go past ~6 posts a day the calendar needs a week view as its default instead.

5. How the AI writing works

In the prototype, yes — the review screen can call Claude live to write real titles, SEO descriptions and keyword sets from your product text, so you are reading genuine output rather than lorem ipsum. That runs inside the prototype and costs you nothing to click.

One caveat worth knowing now, because it shapes the real build: a Claude subscription covers chat, not an app calling the model on a server. A shipped Pin-Post Studio needs an Anthropic API key with its own usage billing. Text is cheap at this volume; the expensive part is image generation for the mockups, which Claude does not do — that would be a separate image model. The prototype uses your dropped product photos in the mockup slots so you can judge the layout before committing to any of that.

6. Workspace rules

Affiliate compliance is a workspace-level rule, not a per-pin checkbox: set "#ad required on affiliate links" once in Connections and every description the AI writes carries it, with a hard block at push time on anything missing it. The same panel holds the other set-once rules — default text overlay and branding, posting window (9am–5pm), maximum posts per network per day, and the default fan-out pattern.

7. The Content360 handoff

Your screenshots show the three pieces this needs: a workspace API id under Settings, connected Pinterest / Facebook page / Instagram profiles, and a Bulk Posts path that already accepts many posts at once with per-platform options (Pinterest wants a title, link and board; Facebook wants post vs reel vs story). Pin-Post Studio's schedule step maps onto exactly those fields.

Their API accepts post creation, so the real build can push a finished run straight in — no CSV, no manual re-entry. In the prototype the handoff is simulated but visible in exactly the shape the API will take: a "Push to Content360" action, a per-post sync badge (queued → pushed → published → failed), and a Connections panel showing the workspace id it pushes into. That makes the integration reviewable before anyone writes a line of API code, and it means the only untested part of the real build is credentials.

8. Suggested build order

  1. Now: react to the hero dashboard screen — density, wording, what you want to see first thing in the morning.
  2. Next: the run wizard (screens 2–6) as a clickable flow with your real product photos.
  3. Then: review grid with live Claude copywriting and the four crop ratios per pin.
  4. Then: fan-out + the cross-network calendar, including the sync badges.
  5. Later, if wanted: mobile companion — a read-only calendar and an approve/reject swipe on the review grid. Nothing in this plan blocks it.
